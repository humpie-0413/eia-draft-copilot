## Reg-0: 경미한 이슈 수정

### 문제
1. 토지이용 서술문이 데이터 3건 있는데 "수집되지 않았다"로 표시 — 비수치형 데이터를 통계 엔진이 인식 못함
2. 부록 B 유사사례 중복 — 동일 사례가 여러 번 반복

### 프롬프트

```
CLAUDE.md, docs/progress/NEXT_CHAT_BRIEF.md, git status를 읽어라. 현재 상태를 요약한 뒤 아래 2가지 이슈만 수정하라. 모든 커밋 메시지, 주석, 문서는 한글로 작성하라.

이슈 1: 토지이용 서술문 불일치

현상: 토지이용 섹션에 데이터 3건(지목, 용도지구, 용도지역구분)이 있지만, 서술문이 "수집되지 않았다"로 표시됨.

원인: narrative_generator와 통계 엔진이 numeric_value가 있는 데이터만 인식하고, 토지이용처럼 텍스트 값(지목: 대, 용도지역: 제2종일반주거지역 등)인 비수치형 데이터를 무시하고 있음.

수정:
- narrative_generator에 비수치형 데이터 처리 로직 추가
- 토지이용 전용 서술문 템플릿 추가:
  "본 사업지역의 토지이용 현황을 조사한 결과, 지목은 {지목}이며, 용도지역은 {용도지역}으로 지정되어 있다. {용도지구가 있으면: '용도지구는 {용도지구}이다.'}"
- 문화재, 기후 등 비수치형 지표가 있는 다른 섹션도 동일하게 처리
- scaffold의 통계 테이블에서 비수치형은 "값 목록" 형태로 표시
- section_planner에서 비수치형 데이터도 충족도 계산에 포함

이슈 2: 부록 B 유사사례 중복

현상: 부록 B에서 화성시 4번, 당진시 4번, 해남군 2번으로 동일 사례 반복 표시.

원인 분석 후 수정:
- export 서비스에서 유사사례를 부록에 출력하는 로직 확인
- 중복 제거 또는 중복 원인 해결
- 유사사례는 고유 사례당 1건만 표시

수정 완료 후 데모 재실행하여 확인:
- 토지이용 서술문이 정상 표시되는가?
- 부록 B에 유사사례가 중복 없이 3건만 표시되는가?
```

## Reg-1: 법령 데이터 구축

### 목표
환경영향평가 관계 법령의 핵심 수치와 규칙을 Python 데이터 구조로 정의한다.

### 프롬프트

```
CLAUDE.md, docs/progress/NEXT_CHAT_BRIEF.md, git status를 읽어라. 현재 상태를 요약한 뒤 Reg-1 (법령 데이터 구축)만 수행하라. 모든 커밋 메시지, 주석, 문서는 한글로 작성하라.

Reg-1 범위:

1. 법령 데이터 폴더 생성 (backend/app/data/regulations/)

2. legal_references.py — 환경기준별 법적 근거 매핑
   기존 env_standards.py의 각 기준값에 법적 근거 조문을 매핑한다.

   대기환경기준:
   - 근거: "환경정책기본법 시행령 별표 제1호 (대기환경기준)"
   - PM10 연평균 50 ug/m3 → "환경정책기본법 시행령 별표 제1호"
   - PM2.5 연평균 15 ug/m3 → "환경정책기본법 시행령 별표 제1호"
   - (나머지 대기 지표 동일)

   수질환경기준:
   - 근거: "환경정책기본법 시행령 별표 제1호 (수질 및 수생태계 환경기준) — 하천 생활환경기준"
   - BOD, COD, SS, DO, T-P, T-N → 등급별 기준

   소음환경기준:
   - 근거: "환경정책기본법 시행령 별표 제1호 (소음환경기준)"

   토양환경기준:
   - 근거: "토양환경보전법 시행규칙 별표 제3호 (토양오염우려기준)"

   구조: 딕셔너리 {indicator → {standard_value, legal_basis, law_name, article}}

3. required_items.py — 사업유형별 필수 평가 항목
   환경영향평가법 시행령 별표 3 기반으로 사업유형별 필수 평가 항목을 정의한다.

   사업유형 분류 (현재 프로젝트의 project_type enum 기준):
   - power_plant (발전소): 대기질, 수질, 소음·진동, 생태, 토지이용 필수
   - road (도로): 대기질, 소음·진동, 생태, 토지이용, 교통 필수
   - housing (주거단지): 대기질, 수질, 소음·진동, 교통, 폐기물 필수
   - industrial (산업단지): 대기질, 수질, 토양, 소음·진동, 폐기물 필수
   - tourism (관광): 생태, 경관, 문화재, 토지이용 필수
   - port (항만): 수질, 소음·진동, 생태, 교통 필수
   - military (군사): 전 항목
   - other (기타): 대기질, 수질, 소음·진동, 토지이용 필수

   구조: 딕셔너리 {project_type → [required_section_keys]}
   각 섹션 내 필수 지표 목록도 포함

4. area_classifications.py — 지역구분별 기준 차등
   소음환경기준의 지역구분 차등을 정의한다.

   소음 지역구분:
   - "가" 지역 (주거, 녹지): 주간 50dB / 야간 40dB (일반) 또는 주간 55dB / 야간 45dB (도로변)
   - "나" 지역 (상업, 준주거): 주간 55dB / 야간 45dB (일반) 또는 주간 60dB / 야간 50dB (도로변)
   - "다" 지역 (공업): 주간 60dB / 야간 50dB (일반) 또는 주간 65dB / 야간 55dB (도로변)
   - "라" 지역 (전용공업): 주간 65dB / 야간 55dB (일반) 또는 주간 70dB / 야간 60dB (도로변)

   대기/수질은 전국 동일 기준이므로 지역구분 불필요.

   구조: 딕셔너리 {area_type → {time_period → standard_value}}

5. env_standards.py 확장
   - 기존 기준값 데이터에 legal_basis 필드 추가
   - legal_references.py와 연동
   - 기존 로직이 깨지지 않도록 하위 호환 유지

6. 테스트 작성
   - 법령 데이터 무결성 테스트 (모든 기준에 법적 근거가 매핑되어 있는지)
   - required_items 완전성 테스트 (모든 project_type에 필수 항목 정의됨)
   - area_classifications 구조 테스트

Reg-2 이후 작업은 착수하지 마라.
```

## Reg-4: 사업유형별 평가 범위 자동 판단

### 목표
프로젝트 유형 입력 시 필수 섹션과 지표를 자동으로 판단하여 사용자에게 안내한다.

### 프롬프트

```
CLAUDE.md, docs/progress/NEXT_CHAT_BRIEF.md, git status를 읽어라. 현재 상태를 요약한 뒤 Reg-4 (사업유형별 평가 범위 자동 판단)만 수행하라. 모든 커밋 메시지, 주석, 문서는 한글로 작성하라.

Reg-4 범위:

1. 평가 범위 서비스 (backend/app/services/scope_service.py)
   - Reg-1의 required_items.py 데이터를 기반으로
   - 프로젝트 유형 입력 시 필수/권장/선택 섹션 분류 반환
   - 각 필수 섹션의 필수 지표 목록 반환
   - API: GET /api/v1/projects/{id}/assessment-scope — 해당 프로젝트의 평가 범위

2. 섹션 플래너 연동
   - section_planner에서 평가 범위를 반영
   - 필수 섹션이 empty면 상태를 expert_required로 표시 (단순 empty가 아닌 "필수인데 비어있음")
   - 선택 섹션이 empty면 not_applicable로 표시 가능

3. 프론트엔드
   - 프로젝트 생성/수정 시 사업유형 선택하면 필수 섹션 목록 안내 표시
   - 섹션 플래너 화면에서 필수/권장/선택 구분 배지 표시
```

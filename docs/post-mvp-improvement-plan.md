## 문제 분석

데모 문서(강남구 태양광) 분석 결과, MVP 파이프라인은 완성되었으나 **실무 사용 수준**까지 다음 문제가 존재한다.

| # | 문제 | 심각도 | 영향 |
|---|------|--------|------|
| 1 | 데이터가 raw 나열 (통계 요약 없음) | 높음 | 문서 가독성 심각 저하 |
| 2 | 환경기준 대비 평가 서술 없음 | 높음 | 평가서 핵심 기능 미비 |
| 3 | 수질 데이터 1992년~현재 무필터 | 중간 | 불필요 데이터 과다 |
| 4 | 11개 섹션 중 7개 미수집 | 중간 | 문서 완성도 저하 |
| 5 | 문서 포맷이 실제 EIA 양식과 차이 | 중간 | 전문성 부족 |
| 6 | LLM 미활용 (서술문 생성 없음) | 낮음 | 텍스트 품질 제한적 |

## Post-1: 데이터 전처리 및 통계 엔진

### 목표
현재 raw 데이터 나열을 **지표별 통계 요약 테이블**로 변환한다.

### 구현 범위
- 백엔드 통계 서비스 (backend/app/services/statistics.py)
  - 지표별: 평균, 최대, 최소, 표준편차, 데이터 건수
  - 시계열: 최근 측정일, 기간 범위
  - 집계: 시간별 → 일평균, 월평균 변환
- 데이터 필터링
  - 수질: 최근 5년 데이터만 사용 옵션
  - 대기: 최근 1년 데이터만 사용 옵션
  - 중복 데이터 제거 로직
- 통계 API
  - GET /api/v1/projects/{id}/statistics (전체)
  - GET /api/v1/projects/{id}/statistics/{section_key} (섹션별)
- scaffold 서비스 수정
  - 기존: 개별 측정값 나열
  - 변경: 통계 요약 테이블 (지표 | 평균 | 최대 | 최소 | 건수 | 기간)
- 테스트 작성

### 프롬프트

```

Post-1 범위:

1. 통계 서비스 구현 (backend/app/services/statistics.py)
   - 프로젝트의 evidence 데이터를 섹션별/지표별로 집계
   - 각 지표별: 평균, 최대값, 최소값, 표준편차, 데이터 건수, 기간(최초~최종 관측일)
   - numeric_value가 있는 evidence만 대상
   - screening_only=False인 본 평가 데이터만 대상

2. 데이터 필터링 옵션
   - 수질 데이터: 최근 5년만 사용하는 필터 (기본 활성화)
   - 대기 데이터: 최근 1년만 사용하는 필터 (기본 활성화)
   - 시간별 raw 데이터를 일평균으로 집계하는 옵션
   - 필터 파라미터는 API 쿼리로 제어 가능하게

3. 통계 API 엔드포인트
   - GET /api/v1/projects/{id}/statistics — 전체 섹션 통계

   - 쿼리 파라미터: years_filter (연도 필터), aggregate_daily (일평균 집계 여부)

4. scaffold 서비스 수정
   - 기존 개별 측정값 나열 방식을 통계 요약 방식으로 변경
   - 각 섹션의 현황 요약: 지표별 1행 요약 테이블 (지표명 | 평균 | 최대 | 최소 | 건수 | 기간)

5. 테스트 작성
   - 통계 계산 정확성 테스트
   - 필터링 동작 테스트
   - scaffold 출력 변경 테스트

Post-2 이후 작업(환경기준 비교, LLM 연동 등)은 착수하지 마라. 논리적 단위마다 커밋하라.

## Post-2: 환경기준 비교 엔진

### 목표
각 지표의 측정값을 **한국 환경기준**과 비교하여 초과 여부를 자동 판정한다.

### 구현 범위
- 환경기준 데이터 정의 (backend/app/data/env_standards.py)
  - 대기: 환경정책기본법 대기환경기준 (PM10 연평균 50, PM2.5 연평균 15, SO2 연평균 0.02 등)
  - 수질: 하천 생활환경기준 (BOD 등급별, COD, SS, DO, T-P 등)
  - 소음: 환경기준 지역구분별 (주거 주간 55dB, 야간 45dB 등)
- 기준 비교 서비스 (backend/app/services/standard_checker.py)
  - 각 지표 평균/최대를 기준과 비교
  - 적합/초과/해당없음 판정
  - 초과율 계산 (전체 중 기준 초과 비율)
- 기준 비교 API
  - GET /api/v1/projects/{id}/standards-check
- scaffold에 기준 비교 결과 반영
  - "PM10 연평균 42 ug/m3으로 환경기준(50 ug/m3) 이내 (적합)" 형식
- QA 규칙 추가
  - R006: 환경기준 초과 시 warning 발생
- 테스트 작성

## Post-3: 초안 텍스트 생성기 고도화

### 목표
통계 + 기준비교 결과를 활용하여 **섹션별 정형 서술문**을 자동 생성한다. LLM 없이 템플릿 기반으로 구현한다.

### 구현 범위
- 서술문 템플릿 엔진 (backend/app/services/narrative_generator.py)
  - 섹션별 서술 템플릿 정의
  - 대기: 현황 서술 → 기준 비교 → 영향 예측 골격 → 저감방안 필요 여부
  - 수질: 수계 현황 → 등급 판정 → 기준 비교 → 영향 예측 골격
  - 소음: 현황 서술 → 기준 비교 → 초과 시 저감방안 언급
  - 생태: 종수 현황 → 보호종 여부 → 녹지자연도
  - 미수집 섹션: "해당 분야 데이터 미수집. 현장조사 필요." 명시
- DOCX/PDF 출력 개선
  - 섹션 구조: 현황 서술문 → 요약 통계 테이블 → 환경기준 비교 테이블 → 상세 데이터 (부록)
  - 서술문이 문서 앞부분에 오도록 재배치
- 프론트엔드 초안 뼈대 화면 업데이트
  - 서술문 미리보기 추가
- 테스트 작성

### 프롬프트

```
CLAUDE.md, docs/progress/NEXT_CHAT_BRIEF.md, git status를 읽어라. 현재 상태를 요약한 뒤 Post-3 (초안 텍스트 생성기 고도화)만 구현하라. 모든 커밋 메시지, 주석, 문서는 한글로 작성하라.

   - LLM을 사용하지 않는 결정적 템플릿 방식
